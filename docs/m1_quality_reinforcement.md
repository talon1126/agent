# M1 导购质量补强变更说明

状态：固定回放与 M1 门禁配置已落地，Kayn 探索评测已运行；独立提交快照复验尚未完成，本文不代表 M1 重新验收通过。

## 为什么需要补强

当前 `AGENT_TASKBOOK.md` 的 D 阶段只要求 D1-D5 的模块验收，M1 退出条件描述了完整导购闭环，但 `config/agent_quality_gates.yaml` 的 D 里程碑没有质量指标。模块测试通过，不能证明真实入口上的比较、推荐理由和多轮对话可用。

2026-09-23 Kayn 评测的 35 个主评分样例中，单轮通过 10/23，多轮通过 0/12；比较 0/6，评论总结 0/5。另有 5 个工具故障样例因没有确定性故障注入而未评分。这份结果反映被测目标的表现，不能直接证明当前工作区的修复无效：运行脚本记录的是磁盘文件指纹，没有证明 Kayn 连接器实际加载了同一版本。现有回归测试还给所有商品设置了固定库存 20，与 mock-api 的真实库存缺失情况不符。

## 拟纳入 M1 的验收

1. 冻结同一版场景、商品与库存快照、期望终态、商品 ID、硬约束和允许的工具调用。至少覆盖无页面上下文、页面候选、单轮、多轮、比较、推荐依据、评论、无候选和约束冲突；故障样例提供可复现的注入方式。
2. 经生产 API 或 Kayn 目标入口执行，记录连接器运行时版本和代码指纹，并与评测清单核对。指纹不一致、样例漏跑、结果未评分或工具故障样例被跳过时，门禁直接失败。
3. 使用确定性断言检查候选集合、价格与规格来源、用户明确的预算/品牌/数量限制、比较矩阵、推荐理由的商品级证据、评论样本及工具权限。LLM Judge 只补充语言质量，不代替这些硬断言。
4. 比较是只读事实任务：库存未知时可展示已核验的价格与规格，不能声称有货；用户明确要求购买数量时仍必须核验库存。推荐必须满足可售事实，不因比较规则而放宽。
5. 建议首轮 M1 门槛：全部样例完成评分；硬约束违规、无证据关键商品事实、越权工具调用均为 0；总体和各核心场景类别的任务成功率均不低于 80%。门槛确定后只在 `config/agent_quality_gates.yaml` 保存可执行数值及分母，不在测试脚本另存一份。
