# AImodel 会话记忆实施计划

## 目标

为 `AImodel` 增加两类记忆：

- 窗口会话记忆：通过 `conversation` 和 `message` 管理当前聊天窗口的上下文。
- 用户长期记忆：通过匿名 `user_id` 记录用户购物偏好，例如喜欢某些品牌、偏好高性价比、偏好某类商品。

首版范围：

- `ai-service` 管理 `conversation`、`message`、`user_memory` 三张表。
- `conversation.id` 是 int 自增主键，不再设计 `conversation.conversation_id` 字段。
- `message.id` 是 int 自增主键。
- `message.conversation_id` 只做逻辑外键，不创建物理外键约束。
- 当前窗口会话每次只注入最近 5 条 `message`。
- 长期记忆按前端本地持久化匿名用户 ID 归属。
- `POST /AImodel/chat` 继续使用现有 SSE 流式接口，不新增接口。
- 工具调用结果只作为后端内部上下文，不写入前端可见 message 正文，不写入长期偏好正文。

## 已确认需求

- 表名：`conversation`。
- `conversation` 主键：`id INT` 自增。
- `conversation.title`：`VARCHAR(40)`。
- 不使用 `conversation.conversation_id` 字段。
- `message` 主键：`id INT` 自增。
- `message.conversation_id` 使用逻辑外键，不建立物理外键。
- 表归属：`ai-service`。
- 窗口记忆：最近 5 条 message。
- 长期记忆：记录用户偏好。
- 用户标识：前端生成本地持久化匿名用户 ID，例如 `localStorage` 中的 `aimodel_user_id`，请求时传给后端。
- 所有新增业务代码必须附带中文注释。
- 不清楚的细节先询问，不擅自扩大范围。

## metadata 字段说明

上一版计划中的 `conversation.metadata` 是预留扩展字段，原本可用于存模型版本、客户端信息、摘要状态等。

本版计划删除 `conversation.metadata`，原因：

- 当前需求已经明确窗口记忆和长期偏好记忆，不需要一个宽泛的 JSON 扩展字段。
- 长期记忆应使用独立 `user_memory` 表承载，避免偏好、客户端状态、模型状态混在一个字段里。
- 表结构更清晰，也更容易写测试和维护。

## 数据库表设计

### conversation

```sql
CREATE TABLE IF NOT EXISTS conversation (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    source VARCHAR(20) NOT NULL DEFAULT 'web',
    title VARCHAR(40),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_conversation_user_updated_at
ON conversation(user_id, updated_at DESC, id DESC);
```

字段说明：

- `id`：会话自增主键，前端和后端通过这个数字 ID 继续当前窗口会话。
- `user_id`：匿名用户 ID，来自前端 `localStorage.aimodel_user_id`。
- `source`：来源，首版固定为 `web`。
- `title`：会话标题，最长 40 字符，首版用第一条用户消息截断生成。
- `created_at` / `updated_at`：用于排序和后续清理。

### message

```sql
CREATE TABLE IF NOT EXISTS message (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    conversation_id INTEGER NOT NULL,
    user_id VARCHAR(64) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('user', 'assistant')),
    content TEXT NOT NULL,
    links JSONB NOT NULL DEFAULT '[]'::jsonb,
    recommended_links JSONB NOT NULL DEFAULT '[]'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_message_conversation_created_at
ON message(conversation_id, created_at DESC, id DESC);

CREATE INDEX IF NOT EXISTS idx_message_user_created_at
ON message(user_id, created_at DESC, id DESC);
```

字段说明：

- `id`：消息自增主键。
- `conversation_id`：逻辑外键，保存 `conversation.id`，不创建物理外键约束。
- `user_id`：匿名用户 ID，方便按用户审计和后续查询。
- `role`：只保存 `user` 和 `assistant`，不保存 system/tool。
- `content`：用户原文或 assistant 最终 answer。
- `links`：用户本轮携带的商品链接，仅 `user` message 使用。
- `recommended_links`：assistant 最终推荐链接，仅 `assistant` message 使用。
- `created_at`：消息时间，用于取最近 5 条。

### user_memory

```sql
CREATE TABLE IF NOT EXISTS user_memory (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    memory_type VARCHAR(40) NOT NULL,
    memory_value VARCHAR(120) NOT NULL,
    evidence TEXT,
    confidence NUMERIC(4, 3) NOT NULL DEFAULT 0.500,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (user_id, memory_type, memory_value)
);

CREATE INDEX IF NOT EXISTS idx_user_memory_user_type
ON user_memory(user_id, memory_type, updated_at DESC);
```

字段说明：

- `id`：长期记忆自增主键。
- `user_id`：匿名用户 ID。
- `memory_type`：偏好类型，例如 `brand_preference`、`price_preference`、`category_preference`。
- `memory_value`：偏好值，例如 `小米`、`高性价比`、`无线耳机`。
- `evidence`：触发偏好记忆的用户表达摘要，例如“用户多次询问高性价比无线耳机”。
- `confidence`：置信度，首版使用 0.500 到 1.000 的简单数值。
- `created_at` / `updated_at`：用于长期记忆排序和更新。

首版长期记忆示例：

```text
user_id=anon_abc
memory_type=price_preference
memory_value=高性价比
evidence=用户询问“如何挑选高性价比的无线耳机”
confidence=0.700
```

```text
user_id=anon_abc
memory_type=brand_preference
memory_value=小米
evidence=用户表达“我比较喜欢小米的产品”
confidence=0.800
```

## API 契约调整

### 请求体

`POST /AImodel/chat` 请求体增加 `user_id`，`conversation_id` 改为数字类型，表示 `conversation.id`：

```json
{
  "user_id": "anon_生成的匿名用户ID",
  "conversation_id": 123,
  "message": "有推荐的解压玩具吗",
  "links": []
}
```

字段规则：

- `user_id`：必填。前端从 `localStorage.aimodel_user_id` 读取；如果不存在则生成并保存。
- `conversation_id`：可选。为空时后端创建新 conversation 并在 `done` 事件返回新 ID。
- `message`：必填。
- `links`：可选。

### SSE done 事件

```text
event: done
data: {"conversation_id":123,"answer":"...","recommended_links":[]}
```

规则：

- `conversation_id` 返回数字 ID。
- 不返回 `tool_results`。
- 不返回长期记忆明细，长期记忆只影响后续上下文。

## 后端模块划分

新增文件：

```text
services/ai-service/app/routers/AImodel/memory.py
```

职责：

- 初始化 `conversation`、`message`、`user_memory` 表。
- 创建或更新 conversation。
- 写入 user message。
- 写入 assistant message。
- 读取某个 conversation 最近 5 条历史 message。
- 读取某个 user 最近/最可信的长期记忆。
- 从用户 message 和 assistant answer 中提取可保存的用户偏好。

建议接口：

```python
@dataclass(frozen=True)
class AiModelMemoryMessage:
    role: Literal["user", "assistant"]
    content: str


@dataclass(frozen=True)
class AiModelUserMemory:
    memory_type: str
    memory_value: str
    evidence: str | None
    confidence: float


class AiModelMemoryStore(Protocol):
    def initialize(self) -> None: ...
    def ensure_conversation(self, conversation_id: int | None, *, user_id: str, first_message: str) -> int: ...
    def load_recent_messages(self, conversation_id: int, *, limit: int = 5) -> list[AiModelMemoryMessage]: ...
    def load_user_memories(self, user_id: str, *, limit: int = 10) -> list[AiModelUserMemory]: ...
    def append_user_message(self, conversation_id: int, *, user_id: str, content: str, links: list[str]) -> None: ...
    def append_assistant_message(
        self,
        conversation_id: int,
        *,
        user_id: str,
        content: str,
        recommended_links: list[dict[str, str]],
    ) -> None: ...
    def upsert_user_memory(
        self,
        user_id: str,
        *,
        memory_type: str,
        memory_value: str,
        evidence: str | None,
        confidence: float,
    ) -> None: ...
```

实现方式：

- `PostgresAiModelMemoryStore`：使用 `psycopg`，风格参考 `services/ai-service/app/session_store.py`。
- `NoopAiModelMemoryStore`：当 `DATABASE_URL` 缺失时使用，保证测试环境不强制依赖数据库。
- `get_aimodel_memory_store()`：使用 `lru_cache(maxsize=1)`，与现有 `get_session_store()` 风格一致。

## 长期记忆提取策略

首版使用规则型提取，不额外调用模型，避免增加不稳定成本。

示例规则：

- 命中“喜欢/偏好/常买/只看 + 品牌名”时，保存 `brand_preference`。
- 命中“高性价比/便宜/实惠/预算有限”时，保存 `price_preference=高性价比`。
- 命中“想买/推荐/挑选 + 商品类别”时，可保存低置信度 `category_preference`。

首版只保存明显偏好，不从一次普通商品查询中强行推断强偏好。

长期记忆注入 LangChain 的格式：

```text
用户长期偏好：
- 价格偏好：高性价比
- 品牌偏好：小米
```

如果没有长期记忆，不注入该段。

## 请求处理流程

当前 `POST /AImodel/chat` 仍然返回 SSE。

新流程：

```text
前端读取或生成 aimodel_user_id
  -> 发送 user_id + conversation_id + message + links
  -> ai-service 创建或确认 conversation.id
  -> 读取该 conversation 最近 5 条 message
  -> 读取该 user_id 的长期偏好记忆
  -> 写入本轮 user message
  -> 将长期偏好 + 历史 message + 当前 user message 转为 LangChain messages
  -> agent 流式生成 delta
  -> 生成完成后写入 assistant message
  -> 根据本轮用户表达 upsert 长期偏好
  -> done 事件返回 conversation_id、answer、recommended_links
```

异常处理：

- 数据库不可用且配置了 `DATABASE_URL`：返回 SSE `error`，避免用户以为记忆已保存。
- 模型调用失败：保留已写入的 user message，不写 assistant message。
- assistant message 写入失败：前端回答已完成时仍返回 done，但后端需要在测试中覆盖异常路径。
- 长期记忆提取失败：不影响当前回答。

## LangChain 记忆注入

改造 `_build_langchain_messages`：

```python
def _build_langchain_messages(
    request: AiModelChatRequest,
    *,
    history: list[AiModelMemoryMessage] | None = None,
    user_memories: list[AiModelUserMemory] | None = None,
) -> list[HumanMessage | AIMessage]:
    ...
```

规则：

- 长期偏好作为当前用户消息前的上下文说明注入。
- 最近 5 条历史 message 按时间正序注入。
- `role=user` 转为 `HumanMessage(content=content)`。
- `role=assistant` 转为 `AIMessage(content=content)`。
- 当前用户问题仍使用现有 `_build_user_prompt(request)`，这样商品链接上下文可以继续随当前请求进入模型。
- 不把工具调用 JSON、工具结果或隐藏推理注入历史。

## 前端改动

新增匿名用户 ID 逻辑：

```ts
function getOrCreateAiModelUserId(): string {
  const storageKey = 'aimodel_user_id'
  const existing = localStorage.getItem(storageKey)
  if (existing) {
    return existing
  }
  const userId = `anon_${crypto.randomUUID()}`
  localStorage.setItem(storageKey, userId)
  return userId
}
```

会话 ID 调整：

- `conversationId` 类型从 string 改为 `number | null`。
- 新聊天窗口首次请求时 `conversation_id=null`。
- 后端 `done` 返回数字 `conversation_id` 后，前端保存到当前窗口状态。
- 本计划不新增会话列表 UI；只实现当前窗口会话记忆。

## 实施顺序

1. 编写 memory store 的失败测试。
2. 新增 `AImodel/memory.py`，实现三张表初始化和读写接口。
3. 在 `main.py` startup 初始化 AImodel memory store。
4. 修改 AImodel schema：增加 `user_id`，`conversation_id` 改为 `int | None`。
5. 改造 `stream_chat_events`：确认 conversation、加载最近 5 条、加载长期偏好、写入 user、流式生成、写入 assistant、upsert 长期偏好。
6. 改造 `_build_langchain_messages` 支持历史 message 和长期偏好。
7. 更新前端类型和请求逻辑：生成 `aimodel_user_id`，传 `user_id`，保存数字 conversation ID。
8. 更新设计文档和 AGENTS 子文档。
9. 跑完整验证命令。
10. 重建 `ai-service`，用真实 Postgres 查询验证表、消息记录和长期偏好。

## 非目标

- 不做会话列表 UI。
- 不做删除会话、重命名会话、分页查询历史。
- 不做跨真实登录账号的身份绑定。
- 不做历史摘要压缩。
- 不把工具调用结果、工具 JSON 或隐藏推理保存为 message。
- 不用模型额外抽取长期偏好，首版只做规则型偏好提取。
