# 购物目标状态合并规则

本文定义 B3 的确定性状态合并边界。合并器只消费已经通过 B1/B2 schema 校验的
`ShoppingGoal` 与 `GoalDelta`，不调用模型、数据库、商品接口，也不读取系统时钟。

## 来源优先级

同一语义字段按以下顺序决策：当前轮用户明确表达、当前页面上下文、历史会话状态、
长期偏好。长期偏好只能填充尚未占用的软偏好槽位。硬约束始终强于软偏好；软偏好
即使来自当前轮，也不能覆盖已经存在的硬约束。

页面上下文和用户表达同时出现时，用户表达胜出。合并器按来源优先级而非操作顺序
决定最终值，因此调换同一轮低优先级与高优先级操作的顺序不会改变最终状态。

## 合并操作

- `add`：为语义字段加入本轮值；本轮来源可以替换较低优先级的历史值。
- `replace`：显式替换同一类型、同一字段及同一规格属性的值，并保留前后证据。
- `remove`：只删除指定字段、规格属性和 `target_kinds`，不影响其他目标。
- `confirm`：相同值会刷新为本轮证据；与现值不一致时产生冲突，不伪装成确认。

已知值写入后会移除同一语义字段的 open slot。重复应用完全相同的增量不会增加
重复约束，也不会继续增加 revision。

## 冲突代码

| code | 含义 | 澄清主题 |
| --- | --- | --- |
| `budget_range_reversed` | 预算下限高于上限 | 预算范围 |
| `brand_included_and_excluded` | 同一品牌同时要求与排除 | 品牌取舍 |
| `specification_mutually_exclusive` | 同一规格值同时要求与排除 | 规格取舍 |
| `delivery_deadline_in_past` | 配送期限早于注入的参考时间 | 配送时间 |
| `confirmation_mismatch` | confirm 值与当前值不一致 | 确认目标 |

冲突字段不会写入 `ShoppingGoal`。合并器回滚该冲突涉及的字段，保留其他无冲突修改，
并返回含冲突值、原始证据和澄清主题的 `GoalConflict`。参考时间由调用方注入；未注入
时只使用增量证据时间推导，不读取机器时钟。

## 阶段迁移

阶段决策顺序为：阻断冲突、必填槽位、候选状态、目标是否改变。

- 有冲突或候选为空：进入 `clarifying`。
- 品类 open slot：进入 `clarifying`；初始状态缺少品类时保持 `discovering`。
- 目标含必填品类且尚未搜索，或目标语义发生变化：进入 `searching`。
- 候选可用：从 `searching` 进入 `comparing`。
- 已选定候选：从 `comparing` 进入 `decided`。
- 未提供新的候选状态且目标语义未变：保留当前阶段。

所有迁移复用 `ShoppingGoal.transition_to` 的合法迁移表。任何跳级都会抛出
`InvalidGoalTransition`，不能通过重建对象绕过。

## 审计事件

每个增量操作产生一个 `GoalChangeEvent`，记录 action、字段、属性、source turn、
变更前值、尝试后的值、结果以及关联冲突码。前后值均携带 B1 `GoalEvidence`，因此
旧值失效后仍可追溯来源。事件只描述本次纯逻辑决策；B5 再负责持久化和并发控制。
