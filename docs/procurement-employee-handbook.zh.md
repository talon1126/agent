# 采购 Agent 员工使用手册

本文档面向采购部门员工，说明如何在飞书中使用 `@procurement` 机器人处理补货请求、同步采购视图、生成采购草稿单和确认到仓。本文会随着采购流程变化持续更新。

## 适用范围

采购 Agent 当前用于处理仓储发起的补货申请和采购草稿单流转。它可以：

- 把数据库中的补货申请同步到飞书多维表格。
- 把采购草稿单同步到飞书多维表格。
- 批量批准待采购审核的补货申请，并生成或复用采购草稿单。
- 按单个 `REQ-*` 批准或驳回补货申请。
- 按 `POD-*` 批量确认采购草稿单已到仓。
- 根据商品 ID 查询基础采购建议。

当前系统连接的是 `mock-procurement`，用于内部流程验证和演示，不代表已经接入真实 ERP 或正式采购下单系统。

## 基本使用规则

在飞书群里使用时，请明确 `@procurement`。如果是私聊采购机器人，可以不加 @。

推荐输入要短、明确，并包含关键编号：

- 补货申请编号使用 `REQ-*`，例如 `REQ-1001`。
- 采购草稿单编号使用 `POD-*`，例如 `POD-5001`。
- 商品编号使用 `item_*`，例如 `item_vinda_tissue`。

不要把多个不相关任务写在同一句话里。例如不要同时要求同步、批准、驳回和到仓确认。拆成多条消息更稳定，也更方便审计。

## 日常流程

### 1. 同步补货请求到飞书

当仓储已经创建补货申请后，采购人员不需要先让机器人“查看待处理补货申请”。直接同步即可。

推荐输入：

```text
@procurement 同步补货请求
```

也可以这样写：

```text
@procurement 刷新补货申请到飞书
@procurement 更新补货视图
```

预期结果：

- 机器人会把 `replenishment_requests` 中的补货申请同步到飞书表 `Procurement Replenishment Requests`。
- 回复里应包含同步是否成功、同步数量、飞书补货请求表链接。
- 飞书表中以 `Request ID` 作为唯一标识，同一个申请重复同步会更新原记录，不会重复新增。

飞书表常见字段包括：

- `Request ID`
- `Status`
- `Item ID`
- `Item Name`
- `Warehouse`
- `Location`
- `Current Available`
- `Reorder Threshold`
- `Suggested Quantity`
- `Reason`
- `Created At`

### 2. 批量批准并生成采购草稿单

当飞书补货请求视图 review 完成，确认全部待审核申请可以采购时，使用批量批准。

推荐输入：

```text
@procurement 批量批准生成采购草稿单
```

也可以这样写：

```text
@procurement 全部批准
@procurement 批量生成采购草稿单
```

预期结果：

- 系统会默认处理全部 `pending_procurement_review` 补货申请。
- 每条可审批申请会生成或复用一条采购草稿单。
- 补货申请状态会更新为 `purchase_order_draft_created`。
- 采购草稿单会写入数据库，并同步到飞书表 `Procurement Purchase Order Drafts`。
- 补货请求表和采购草稿单表都会自动刷新。

机器人回复必须包含：

- 处理数量。
- 批准数量。
- 生成或复用草稿单数量。
- 跳过数量。
- 飞书补货请求表链接。
- 飞书采购草稿表链接。
- 异常明细。
- 下一步。

如果某个商品没有默认供应商，批量批准不会中断整批任务。该申请会被跳过，并在异常明细中说明原因。

### 3. 同步采购草稿单到飞书

如果只想刷新采购草稿单视图，可以单独同步。

推荐输入：

```text
@procurement 同步采购草稿
```

也可以这样写：

```text
@procurement 刷新采购单草稿视图
@procurement 同步采购单草稿
```

预期结果：

- 机器人会把 `purchase_order_drafts` 中的采购草稿单同步到飞书表 `Procurement Purchase Order Drafts`。
- 回复里应包含同步是否成功、同步数量、飞书采购草稿表链接。
- 飞书表中以 `PO Draft ID` 作为唯一标识，同一个草稿单重复同步会更新原记录，不会重复新增。

飞书表常见字段包括：

- `PO Draft ID`
- `Request ID`
- `Status`
- `Supplier`
- `Item ID`
- `Item Name`
- `Warehouse`
- `Location`
- `Quantity`
- `Unit Price`
- `Estimated Total Price`
- `Lead Time Days`
- `Estimated Arrival Date`
- `Created At`

### 4. 单个补货申请批准

如果只想批准某一条补货申请，必须写明 `REQ-*` 编号。

推荐输入：

```text
@procurement 批准 REQ-1001 生成采购草稿单
```

也可以这样写：

```text
@procurement 同意采购 REQ-1001
@procurement 为 REQ-1001 创建采购草稿
```

预期结果：

- 该补货申请状态更新为 `purchase_order_draft_created`。
- 系统生成或复用一条采购草稿单。
- 如果之前已经批准过同一个 `REQ-*`，再次批准会返回已有草稿单，不会重复创建。

机器人回复必须包含：

- `request_id`
- 新状态
- `po_draft_id`
- 供应商
- 商品
- 仓库
- 库位
- 建议采购量
- 单价
- 预计总价
- 交期
- 预计到达时间
- 下一步

如果没有写 `REQ-*`，机器人会要求补充申请编号。

### 5. 单个补货申请驳回

如果不采购某条补货申请，必须写明 `REQ-*` 编号，并建议写清楚原因。

推荐输入：

```text
@procurement 驳回 REQ-1001，原因：库存已调拨覆盖，暂不采购
```

也可以这样写：

```text
@procurement 拒绝 REQ-1001，原因：供应商价格异常，先人工复核
@procurement REQ-1001 暂不采购，原因：仓库复盘后不缺货
```

预期结果：

- 该补货申请状态更新为 `rejected`。
- 不会创建采购草稿单。
- 拒绝原因会记录在申请中，便于后续审计。

机器人回复必须包含：

- `request_id`
- 新状态
- 商品
- 仓库
- 库位
- 拒绝原因
- 下一步

### 6. 确认采购草稿单已到仓

当供应商到货，采购人员需要把采购草稿单确认到仓。支持一次确认一个或多个 `POD-*`。

推荐输入：

```text
@procurement POD-5001 已到仓库
```

批量输入：

```text
@procurement POD-5001,POD-5002 已到仓库
```

预期结果：

- 采购草稿单状态更新为 `received_at_warehouse`。
- 系统写入仓库库存入库批次，批次号类似 `RCV-POD-5001`。
- 采购草稿单飞书表会自动刷新。
- 系统会生成库存同步任务，后续由 Warehouse Agent 消费并刷新仓储库存飞书视图。

机器人回复必须包含：

- 处理数量。
- 确认到仓数量。
- 跳过数量。
- `POD-*` 编号。
- 商品。
- 仓库。
- 库位。
- 入库批次。
- 入库数量。
- 采购草稿表同步结果。
- 下一步通知 Warehouse 处理库存同步任务。

到仓确认后，建议通知仓储：

```text
@warehouse 处理库存同步任务
```

Warehouse Agent 会消费待处理库存同步任务，把对应商品、仓库和库位的库存事实刷新到飞书库存视图。

### 7. 查询采购建议

如果只是想查看某个商品是否建议补货，可以输入商品编号。

推荐输入：

```text
@procurement item_vinda_tissue 是否需要补货？给出采购建议
```

预期结果：

- 机器人会返回 mock 采购建议。
- 回复会说明是否建议补货、库存依据和下一步。

该能力只用于参考，不会自动创建补货申请，也不会生成采购草稿单。

## 状态说明

补货申请主要状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `pending_procurement_review` | 仓储已提交，等待采购 review | 同步到飞书，采购 review 后批准或驳回 |
| `purchase_order_draft_created` | 采购已批准，并已生成或复用采购草稿单 | 等待供应商到货，后续确认到仓 |
| `rejected` | 采购已驳回 | 根据拒绝原因由仓储或采购人工处理 |

采购草稿单主要状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `draft` | 采购草稿单已创建，等待后续处理 | 跟进供应商、预计到达时间和到货情况 |
| `received_at_warehouse` | 采购草稿单已确认到仓 | 通知 Warehouse Agent 处理库存同步任务 |

## 输入规范

推荐写法：

| 目的 | 推荐输入 |
| --- | --- |
| 同步补货请求 | `@procurement 同步补货请求` |
| 同步采购草稿 | `@procurement 同步采购草稿` |
| 批量批准 | `@procurement 批量批准生成采购草稿单` |
| 单条批准 | `@procurement 批准 REQ-1001 生成采购草稿单` |
| 单条驳回 | `@procurement 驳回 REQ-1001，原因：库存已调拨覆盖，暂不采购` |
| 到仓确认 | `@procurement POD-5001,POD-5002 已到仓库` |
| 采购建议 | `@procurement item_vinda_tissue 是否需要补货？给出采购建议` |

不推荐写法：

| 不推荐输入 | 问题 |
| --- | --- |
| `帮我处理一下` | 缺少具体动作，机器人无法判断是同步、批准、驳回还是到仓 |
| `批准这个` | 缺少 `REQ-*` 编号 |
| `这些都到了` | 缺少 `POD-*` 编号 |
| `把飞书弄一下` | 缺少要同步的表类型 |
| `批准 REQ-1001 但是 REQ-1002 不要采购，然后 POD-5001 到仓` | 多个动作混在一起，建议拆成三条消息 |

## 常见异常和处理方式

### 机器人要求提供申请编号

原因：批准或驳回时没有写 `REQ-*`。

处理方式：重新发送包含申请编号的消息。

```text
@procurement 批准 REQ-1001 生成采购草稿单
```

### 批量批准时有跳过记录

常见原因：

- 商品没有配置默认供应商。
- 申请状态已经不是 `pending_procurement_review`。
- 申请数据不完整，需要人工复核。

处理方式：

- 先查看机器人回复中的异常明细。
- 对供应商缺失的问题，联系系统维护人员补充默认供应商配置。
- 补齐后可以再次执行批量批准。已成功的申请不会重复创建草稿单。

### 飞书表没有看到最新数据

处理方式：

1. 先重新发送同步命令：

   ```text
   @procurement 同步补货请求
   @procurement 同步采购草稿
   ```

2. 确认机器人回复里有飞书表链接和同步成功信息。
3. 检查飞书表是否切换到了正确表：

   - `Procurement Replenishment Requests`
   - `Procurement Purchase Order Drafts`

4. 如果机器人没有回复，联系系统维护人员检查 Feishu Adapter、n8n Procurement Workflow 和 mock-api 运行状态。

### 到仓确认后库存视图没有变化

到仓确认只负责把采购草稿单标记为到仓，并创建库存入库批次和库存同步任务。仓储库存飞书视图由 Warehouse Agent 刷新。

处理方式：通知仓储执行：

```text
@warehouse 处理库存同步任务
```

## 数据边界

采购 Agent 不直接修改仓储库存主数据。到仓确认后，系统会写入入库批次并创建库存同步任务，再由 Warehouse Agent 刷新库存视图。

飞书多维表格是只读业务视图，不是源系统。员工可以在飞书中 review 数据，但不要把手工编辑飞书表当成数据库回写。当前同步策略是从数据库刷新到飞书。

采购草稿单不是正式采购订单。当前流程只生成可追踪的采购草稿，正式下单、合同、付款、收票等流程不在本阶段范围内。

## 推荐工作节奏

每日或每次仓储发出补货后：

1. 发送 `@procurement 同步补货请求`。
2. 在飞书表 `Procurement Replenishment Requests` 中 review 商品、仓库、库位和建议采购量。
3. 对确认采购的申请发送 `@procurement 批量批准生成采购草稿单`，或按单条 `REQ-*` 批准。
4. 对不采购的申请发送驳回消息并写明原因。
5. 发送 `@procurement 同步采购草稿` 检查草稿单视图。
6. 供应商到货后发送 `@procurement POD-xxxx 已到仓库`。
7. 通知仓储发送 `@warehouse 处理库存同步任务`。

## 维护与持续更新

本文档应在以下情况更新：

- 新增或删除采购 Agent 支持的话术。
- 采购 workflow 新增工具或调整回复格式。
- 飞书表字段、表名、唯一键或同步策略变化。
- 采购草稿单状态流发生变化。
- 到仓确认、库存同步任务或跨部门协作方式变化。
- 接入真实 ERP、供应商系统或正式采购单系统。

建议更新方式：

1. 修改本文档对应章节。
2. 在下方更新记录中增加一条记录。
3. 如果话术变化，同时更新 n8n Procurement Workflow 的 prompt 和相关测试。
4. 如果字段变化，同时更新 mock-api、feishu-adapter 和飞书表 schema。
