# DEV_SPEC.md 中文模板

Use this template as a starting point. Adapt section depth to the project size.

## 1. 项目概述

### 1.1 项目定位

说明项目要解决什么问题、服务谁、边界是什么。

### 1.2 设计理念

突出架构设计原则，例如模块化、本地优先、可观测、可测试、可扩展。

## 2. 核心特点

用短段落快速说明项目亮点。每个亮点建议包含：

- 这个能力是什么
- 为什么有价值
- 和普通实现相比的区别

示例亮点：

- **可插拔架构**：上层业务只依赖抽象接口，具体实现通过配置和工厂切换。
- **全链路可观测**：关键 pipeline 阶段都有 trace，方便解释结果来源和定位问题。
- **TDD 驱动排期**：每个开发任务都绑定验收标准和测试方法。

## 3. 技术选型

### 3.1 核心流水线设计

用表格说明每一层职责：

| 层级 | 职责 | 关键实现要素 |
| --- | --- | --- |
| Loader | 将输入转成标准对象 | 去重、解析、metadata |
| Splitter | 切分内容 | 语义边界、上下文保留 |
| Transform | 二次加工 | 重写、合并、去噪、增强 |
| Storage | 持久化 | upsert、索引、事务 |
| Query | 检索查询 | 预处理、召回、过滤、重排、引用 |

### 3.2 可插拔架构

说明接口隔离、工厂模式、配置驱动、优雅降级。

### 3.3 配置设计

给出 `settings.yaml` 示例或配置项说明。

### 3.4 可观测性设计

说明 trace、日志、dashboard、指标。

### 3.5 其他专项设计

按项目需要加入安全、权限、多模态、缓存、异步任务、部署等专项设计。

## 4. 测试方案（TDD）

### 4.1 TDD 原则

- 早测试、常测试
- 测试即文档
- 快速反馈循环
- 分层测试金字塔

### 4.2 测试分层

| 层级 | 测试类型 | 目标 | 示例 |
| --- | --- | --- | --- |
| 底层 | 单元测试 | 验证独立组件 | 配置、工具函数、策略类 |
| 中层 | 集成测试 | 验证模块协作 | pipeline、repository、API |
| 顶层 | E2E 测试 | 验证用户路径 | 从输入到输出完整链路 |
| 质量评估 | 指标测试 | 验证效果 | 准确率、召回率、延迟 |

## 5. 系统架构与模块设计

### 5.1 整体架构图

Use Mermaid or ASCII. Example:

```text
User/API
  -> Core Service
  -> Pipeline
  -> Storage
  -> Observability
```

### 5.2 目录结构树

```text
project/
├── README.md                       # 项目说明
├── config/                         # 配置文件
├── src/                            # 业务代码
│   ├── core/                       # 核心业务层
│   ├── libs/                       # 可插拔抽象与实现
│   ├── storage/                    # 持久化层
│   └── scripts/                    # 本地脚本入口
└── tests/                          # 测试
```

### 5.3 模块职责说明表

按层级拆分，每个模块具体到文件：

| 文件 | 具体职责 | 关键技术点 |
| --- | --- | --- |
| `src/core/service.py` | 编排核心流程 | 调用接口、处理异常、写 trace |

### 5.4 数据流说明

至少包含主要业务流。每条数据流建议用垂直文本流程图。

```text
[1] 输入
    |
    v
[2] 处理
    |
    v
[3] 输出
```
